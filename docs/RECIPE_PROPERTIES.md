# Recipe properties

Generated by `tools/gen_recipe_properties_doc.py` from the engine's own reflection (`mods/recipedump`): the 86 item templates that carry a `gCRecipe_PS` (the recipes of all stations), their property sets and the ingredient/skill arrays as shipped. The hand-written sections are the decompiled facts of [`RE.md`](RE.md) section 30 (Script.dll `PSInventory::CanSynthesize/Synthesize`, Script_Game.dll station scripts). Edit recipes with `risen.balance.apply { recipes = { ... } }` / `new_recipes`, `risen.recipe.*` (see [`LUA_API.md`](LUA_API.md) "Recipes").

## How crafting works

* **A recipe is an item.** Any item template with a `gCRecipe_PS` property set (property set id `0x5a`) is a recipe: `Craft` (the station category, enum `gERecipeCategory`), `CraftIngredients` (`bTObjArray<gCCraftIngredient>`, each `ItemTemplate` + `ItemAmount`), `RequiredSkills` (`bTObjArray<gCSkillValue>`: the crafter's skills), `ResultItem` and `ResultAmount`.
* **A character knows a recipe by carrying the recipe item.** There is no list of learned recipes and no recipe game variable: the stations list the stacks of the inventory whose template has a recipe of their category (`InvFilter_Craft_<Station>` sets the select limit of each stack to `CanSynthesize`, `HasRecipes(category)` is what the station's `CanInteract_Player_*` asks). Selling or dropping the item forgets the recipe, picking up or buying one learns it. Alchemy, cooking and scroll recipes are separate recipe items (`It_Recipe_*`, ...); **the smithing recipes are the intermediate blades themselves** (`It_1H_Steel_Raw` is the forge recipe whose ingredient is itself and whose result is `It_1H_Steel_Hot`, which is the anvil recipe for `It_1H_Steel_Shaped`, ...): carrying the blank is knowing how to work it.
* **The check** is `PSInventory::CanSynthesize(recipe)`: 0 unless the crafter meets every `RequiredSkills` entry (`PSSkills::GetTotal >= Amount`), otherwise the smallest `amount in inventory / ItemAmount` over all ingredients (all stacks of the template count). **The craft** is `PSInventory::Synthesize(recipe, count)`: for every ingredient `DeleteItems(first stack, ItemAmount * count)`, then `CreateItems(ResultItem, count)`. It does **not** check anything itself and **never reads `ResultAmount`** (verified: 3 stays 1 per craft), so a recipe makes `count` result items per craft; every station calls it only for an amount the check allowed.
* **The stations** (`Interact_Player_<Station>`, Script_Game.dll): the player uses the mob (`Object_Interact_*`, use type Anvil, Forge, ...): `CanInteract_Player_*` asks for the skill (Smith >= 1 / Alchemy >= 1), a tool (`It_SmithHammer` at the anvil) and a recipe item of the category; `PreInteract_Player_*` walks to the mob and opens the station's inventory page (`GUI2::OpenAnvil` ...: the inventory filtered by `InvFilter_Craft_*`); the click on a recipe is the script `InvEvent_OnClick_CraftSelect` (`SetSelection(stack, 1)`, closes the page; with a select limit above 1 it asks for the amount first); `Interact_Player_*` plays the animation and calls `PSInventory::Synthesize(recipe item, selected amount)`. The smith chain carries the half-finished blade in the left hand between the stations (`CanInteract_Player`: "CarryToAnvil"). `risen.interact.begin` starts it all.
* **Result item and number of results**: the result is any item template (a new one made with `new_items` works the same); `ResultAmount` is data without effect.

## Where the numbers live

| What | Where | Notes |
|---|---|---|
| station | `gCRecipe_PS.Craft` (`station` in `recipes` / `new_recipes`) | enum `gERecipeCategory`: `forge` = `gERecipeCategory_Smith_Forge`, `anvil` = `gERecipeCategory_Smith_Anvil`, `coolweapon` = `gERecipeCategory_Smith_CoolWeapon`, `grindstone` = `gERecipeCategory_Smith_GrindStone`, `goldsmith` = `gERecipeCategory_Goldsmith`, `alchemy` = `gERecipeCategory_Alchemy`, `scroll` = `gERecipeCategory_WriteScroll`, `cooking` = `gERecipeCategory_Cooking`, `frying` = `gERecipeCategory_Frying`; the scripts compare the numbers alchemy 0, forge 6, anvil 7, coolweapon 8, grindstone 9 |
| ingredients | `gCRecipe_PS.CraftIngredients` (`ingredients`, `counts`) | array of `{ ItemTemplate, ItemAmount }` at `+0x30` of the set, stride `0x18`; written through `gCRecipe_PS::SetCraftIngredients` |
| required skills | `gCRecipe_PS.RequiredSkills` (`skills`) | same element type as `gCItem_PS.RequiredSkills` (`Smith`, `Alchemy`, `Scribe`, ...); array at `+0x40`; `gCRecipe_PS::SetRequiredSkills` |
| result | `gCRecipe_PS.ResultItem` (`result`) | a template proxy at `+0x50`; `ResultAmount` (+0x58) is not used by the craft |
| the recipe item | `gCItem_PS` (value, icon, category `Written` for recipe items), loc ids `FO_<template>` / `ITEMDESC_<template>` | like any item; `risen.template.create` clones it |
| tool and skill of the station | scripts `CanInteract_Player_<Station>` (Smith >= 1 or Alchemy >= 1, `It_SmithHammer` at the anvil) | fixed in the scripts |
